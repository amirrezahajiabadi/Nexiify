# 📱 Nexify — نقشه‌ی راه ریسپانسیو (Responsive Roadmap)

> هدف: تجربه‌ی موبایل در حد دسکتاپ — چیدمان روان، لمس‌پذیری درست، بدون اسکرول افقی، سرعت خوب.
> تاریخ شروع: ۸ اوت ۲۰۲۶ — وضعیت فعلی در بخش ۳.

---

## ۱) اصول و استراتژی

**بریک‌پوینت‌های یکپارچه (هماهنگ‌سازی همه‌ی فایل‌ها):**
| نام | عرض | هدف |
|-----|------|-----|
| `xl` | ≤1200px | لپ‌تاپ/تبلت افقی |
| `lg` | ≤1024px | تبلت افقی / لپ‌تاپ کوچک |
| `md` | ≤768px | تبلت عمودی / موبایل بزرگ |
| `sm` | ≤520px | موبایل استاندارد (۳۶۰–۴۸۰) |
| `xs` | ≤360px | موبایل کوچک (iPhone SE و...) |

- **اول موبایل (Mobile-First)**: قوانین پایه برای موبایل نوشته شوند و با `min-width` بزرگ شوند.
- **اسکرول افقی = باگ**: هیچ‌وقت در موبایل `overflow-x` ناخواسته نباشد (بخش ۵ چک‌لیست).
- **لمس**: هدف لمس ≥44px، فاصله‌ی بین المان‌های تعاملی ≥8px.
- **اوب‌رهاو فقط `transform/opacity`** (GPU) — قانون فعلی پروژه حفظ شود.

## ۲) فازها

### فاز R1 — پایه و ایمنی (اولویت بالا)
- [x] **هدر موبایل**: دکمه‌های ورود/ثبت‌نام در هدر موبایل فشرده و همیشه نمایان شد (قبلاً `display:none` بود). حالت واردشده (چیپ + خروج) هم فشرده شد؛ در ≤480px نام کاربری مخفی می‌شود و فقط آواتار می‌ماند. *(انجام شد — ۸ اوت ۲۰۲۶)*
- [x] `body { overflow-x: hidden; }` + چک منبع اسکرول افقی (اُرب‌های auth، مودال پروژه‌ها، preloader). *(از قبل بود — تأیید شد)*
- [x] جایگزینی `100vh` منوی موبایل با `100dvh` (+ fallback `100vh`) — مشکل نوار آدرس مرورگر موبایل. *(انجام شد)*
- [x] `env(safe-area-inset-*)` برای نوبار/فوتر در آیفون‌های ناچ‌دار. *(انجام شد — navbar top + footer bottom)*
- [x] `-webkit-tap-highlight-color: transparent` روی body + حالت `:active` واضح برای دکمه‌ها. *(انجام شد)*
- [x] `touch-action: manipulation` روی دکمه‌ها/لینک‌ها (حذف تأخیر ۳۰۰ms کلیک). *(انجام شد — a/button/input/select/textarea)*

### فاز R2 — صفحات احراز هویت (auth) ← **بزرگ‌ترین شکاف فعلی** *(انجام شد — ۸ اوت ۲۰۲۶)*
- [x] اینپوت‌ها در موبایل `font-size: 1rem` (≥16px — جلوگیری از زوم خودکار iOS). *(در style.css سراسری — فرم تماس هم سود می‌برد)*
- [x] اُرب‌های پس‌زمینه در موبایل کوچک‌تر (۳۴۰/۳۰۰/۲۰۰px) و کم‌رنگ‌تر (`opacity: 0.22` — blur گران است)؛ `.auth-section` از قبل overflow:hidden داشت.
- [x] دکمه‌ی نمایش رمز در موبایل ۴۰×۴۰px (هدف لمس بزرگ‌تر).
- [x] `.auth-section` از `100dvh` استفاده می‌کند.
- [x] تأیید: کارت در ۳۶۰px فیت است (۲۷۶px) و بدون اسکرول افقی.
- [ ] فونت/فاصله‌ی عنوان‌ها در ۳۲۰px — چک نهایی روی گوشی واقعی.

### فاز R3 — صفحه‌ی اصلی (index) *(انجام شد — ۸ اوت ۲۰۲۶)*
- [x] هیرو: `min-height: 100dvh` اضافه شد؛ عنوان در موبایل `2rem` (≤768) و `1.85rem` (≤480) با خط‌شکست درست.
- [x] ردیف آمار: در موبایل با `min-width: 140px` خودکار ۲×۲ می‌شود (تأیید شد: ۲ ردیف × ۲ ستون در ۳۶۰px). در ≤480px مقدارها `2rem`، گپ ۲۴px و `min-width: 120px`.
- [x] Bento خدمات: تک‌ستونه ✅ (قبلاً بود).
- [x] پس‌زمینه‌های متحرک در موبایل: `.bg-gradient-mesh` opacity 0.18، `#neuralCanvas` 0.3، `.bg-particles` 0.35 — (JS هم از قبل ذرات کم‌تری در موبایل می‌ساخت).

### فاز R4 — صفحات داخلی
- [ ] **services**: گرید کارت‌ها در 640px — چک ۱ ستونه، badge «به‌زودی»، spotlight موس غیرفعال روی تاچ (قانون `(hover:none)` موجود — چک شود).
- [ ] **projects**: گرید + مودال جزئیات در موبایل — مودال scrollable، دکمه‌ی بستن در دسترس، تگ‌ها wrap.
- [ ] **blog**: لیست (2→1 ستونه) + جزئیات مقاله (`max-width:760px`) + فیلد خبرنامه تمام‌عرض ✅ (موجود است).
- [ ] **about**: تایم‌لاین در موبایل (فعلاً فقط 768px) — چک ستون سال/متن، نوار مهارت‌ها، گرید ارزش‌ها.
- [x] **contact**: فرم (فقط 768/520 دارد) — چک کارت‌های info (ایمیل/گیت‌هاب/موقعیت) و سلکت سفارشی dropdown در 360px.
  - **باگ سرریز رفع شد**: اینپوت‌ها عرض ذاتی ~490px دارند که ستون‌های grid را از کانتینر بیرون می‌زد (فرم 536px داخل لِی‌اوت 515px). رفع: `repeat(2, minmax(0,1fr))` در `.form-row` و `.contact-method-group`، `min-width:0` روی `.form-input/.form-textarea` (سراسری در style.css)، `minmax(0,1fr)` در لِی‌اوت موبایل + `min-width:0` روی `.form-card` و `.contact-info-cards`. حالا فرم دقیقاً داخل ستون (515=515 و در سیم‌ 360px → 280px) — تأیید با اندازه‌گیری.
  - **یافته‌ی مهم**: scrollWidth ~10000px در صفحه = هانی‌پات (`left:-9999px`) و منوی موبایل بسته (`position:fixed`) — عمدی و بی‌خطر (body `overflow-x:hidden` دارد).

### فاز R5 — تایپوگرافی و فاصله‌گذاری
- [x] مقیاس تایپوگرافی موبایل: `clamp()` برای h1–h3 (الگو: `clamp(2rem, 4vw, 3.5rem)`).
  - از قبل: `.hero-title` `clamp(2.5rem,5.2vw,4.2rem)`، `.page-title` `clamp(2.5rem,5vw,4.5rem)`، `.cta-title` `clamp(2rem,4vw,3.5rem)` ✅
  - اضافه شد: `.newsletter-title` `clamp(1.5rem,3.5vw,1.8rem)`، `.about-text-panel h2` `clamp(1.5rem,3vw,1.8rem)`. تیترهای کارت‌ها (۱.۲–۱.۴rem) در موبایل مناسب‌اند — نیازی به clamp ندارند.
- [x] `section { padding }` در موبایل: ۱۴۰px → ۱۰۰px (≤768) → **۷۲px (≤480)**؛ `.page-header` → ۸۸px/۴۰px؛ `.newsletter-section` → ۸۰px؛ `.faq-section-wrap` → ۷۲px/۸۰px.
- [x] فاصله‌ی خط و پاراگراف: `.page-desc` در ≤480 → `1rem` + `line-height: 1.9`؛ `.section-label` margin-bottom ۶۴px → ۴۰px. (بدنه `line-height: 1.6` از قبل خوب است؛ `.hero-subtitle` خط‌فاصله ۲ برای RTL عمدی.)

### فاز R6 — پرفورمنس موبایل
- [x] **Lenis در تاچ**: `smoothTouch:false` بود (اسکرول بومی) — حالا در `(hover:none)` **اصلاً ساخته نمی‌شود** (گارد `(hover:hover) and (pointer:fine)` در `main.js`)؛ موبایل از `window.scrollTo`/`scrollIntoView` با `behavior:'smooth'` استفاده می‌کند.
- [x] **Canvas شبکه‌ی عصبی** (`index.js`): گارد `prefers-reduced-motion` → فقط یک فریم ثابت (بدون حلقه‌ی rAF)؛ در `(hover:none)` ذرات خیلی کمتر (`/90000` به‌جای `/50000`) + حلقه ۳۰fps (هر فریم دوم).
- [x] **ذرات شناور**: در `prefers-reduced-motion` اصلاً ساخته نمی‌شوند.
- [x] **فونت‌ها**: `font-display: swap` ✅ + preload هر دو فونت (Vazirmatn + JetBrains Mono) در `base.html` ✅.
- [ ] چک Lighthouse Mobile (Performance/Accessibility) قبل و بعد — به‌عنوان قدم مستقل (ابزار خارجی).
